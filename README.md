# 🚦 SignalSense — Traffic Signal & Violation Analytics (Machine Learning Project)

An end-to-end **Machine Learning** project (classical ML only — no deep learning) built on the Smart Traffic Signal & Violation Analytics dataset (15 junctions, 6 months, 26,000 vehicle observations). Covers the full pipeline: data cleaning → EDA → feature engineering → supervised classification → multiclass classification → regression → unsupervised clustering → model evaluation → saved deployable artifacts.

## 🎯 Problems solved

| # | Task | Type | Model used | Key metric |
|---|---|---|---|---|
| 1 | Will this vehicle commit a rule violation? | Binary classification | Random Forest (best of 3) | ROC-AUC 0.72 |
| 2 | Given a violation, which type is it? | Multiclass classification | Random Forest | Macro-F1 0.37, Accuracy 0.63 |
| 3 | How long will a vehicle wait at the signal? | Regression | Random Forest (best of 2) | R² 0.947, MAE 4.4s |
| 4 | Which junctions form natural risk segments? | Unsupervised clustering | K-Means (k=3, silhouette-selected) | Silhouette 0.30 |

## 📊 Results

### 1. Violation classifier (binary)

| Model | Accuracy | Precision | Recall | F1 | ROC-AUC |
|---|---|---|---|---|---|
| Logistic Regression | 0.658 | 0.539 | 0.586 | 0.561 | 0.702 |
| **Random Forest (best)** | **0.776** | **0.983** | 0.407 | 0.575 | **0.718** |
| Gradient Boosting | 0.776 | 0.990 | 0.404 | 0.574 | 0.718 |

**Design note (important):** features like `Helmet`, `Seat_Belt`, `Phone_Usage`, `Lane_Compliance` were deliberately **excluded** from this model, even though they're in the raw data. Those flags are the direct rule-inputs that *define* the violation label — including them would make the task a trivial lookup (>99% accuracy) rather than genuine prediction. Instead the model predicts violation risk from **contextual** signals only — time of day, weather, vehicle type, speed relative to the limit, traffic density, signal state — which is the realistic use case (predicting risk *before* observing driver behavior). That's why ROC-AUC sits at ~0.72 rather than ~1.0, and it's the correct, leakage-free number to report.

### 2. Violation type classifier (multiclass, 8 classes)

Accuracy 0.63, Macro-F1 0.37. `Over Speeding` is predicted perfectly (it's deterministically `Speed > Speed_Limit`, which is in the feature set). `No Helmet` / `No Seat Belt` get reasonable lift from `Vehicle_Type`. Classes like `Mobile Phone Usage`, `Wrong Lane`, `Illegal U-Turn` are close to random in the source data (independent random flags in the underlying generation process) so the model correctly can't beat chance on those — a useful, honest finding rather than a limitation to hide.

### 3. Waiting time regressor

Random Forest reaches **R² = 0.947, MAE = 4.4 seconds** — waiting time is strongly determined by signal timing + traffic density, so this is a genuinely learnable, high-value regression (useful for "what happens if we retime this signal?" simulations).

### 4. Junction risk clustering (unsupervised)

K-Means with k chosen by silhouette score (k=3: **Low / Medium / High Risk**) on violation rate, accident rate, avg speed-over-limit, density, waiting time, and signal efficiency. Cross-checked against the rule-based risk score used in the BI dashboard — the two approaches agree on the top risk junctions (Industrial Area, Civil Lines, Railway Station, Tech Park, Highway Entry, Bus Depot).

## 🚀 How to run

**Option A — step-by-step scripts:**
```bash
pip install -r requirements.txt
python src/01_data_cleaning.py          # reads data/*.csv -> writes data/traffic_cleaned.csv
python src/02_eda.py
python src/03_train_violation_classifier.py
python src/04_train_violation_type_classifier.py
python src/05_junction_risk_clustering.py
python src/06_train_waiting_time_regressor.py
python src/predict_demo.py     # try it on a new sample
```

**Option B — one notebook:**
```bash
jupyter notebook Traffic_ML_Project.ipynb   # Run All — cleans data, trains & saves all 4 models
```

**Option C — interactive dashboard (after models are trained/saved):**
```bash
streamlit run app.py
```
Opens a 6-page dashboard in the browser: Executive Overview, EDA, and three **live prediction pages** (violation risk, violation type, waiting time) plus a Junction Risk Explorer — all backed by the actual saved models, not mock data.

> **Important:** `app.py` and scripts 02–06 all read `data/traffic_cleaned.csv`. Run `python src/01_data_cleaning.py` (or the notebook) **first** — it generates that file from the raw CSVs.

## 🧠 Techniques demonstrated

- Data cleaning: mixed-format date/time parsing, categorical standardization, dedup, null handling
- Feature engineering: peak-hour flags, weekend flags, speed-over-limit, signal efficiency
- `ColumnTransformer` + `Pipeline` (scikit-learn) for reproducible preprocessing
- Model comparison across linear (Logistic/Linear Regression) and ensemble (Random Forest, Gradient Boosting) methods
- Class imbalance handling (`class_weight="balanced"`)
- **Data leakage avoidance** — a deliberate, documented feature-exclusion decision (see above)
- Multiclass classification with label encoding
- Regression evaluation (MAE, RMSE, R²)
- Unsupervised learning: K-Means + silhouette-score model selection + PCA visualization
- Model persistence with `joblib` for reuse/deployment
